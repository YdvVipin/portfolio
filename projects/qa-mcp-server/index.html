The Decision

The brief was "turn these four flows into four AI agents." The right answer was two agents, seven tools, and one server — and the reasoning is the deliverable.

An agent earns its cost when the next step depends on what the last step saw. Anything else is a function call with a language model bolted to the front of it, paying latency and hallucination risk for nothing. Each candidate flow got held against that test.

Agent — earns it

Self-healing

Run the test, read the failure, repair it, re-run, bounded by a retry budget. Every step is conditioned on the previous result. This is a real loop and it already worked that way.

Agent — earns it

Test creation

Qualifies once it can inspect a live DOM rather than guess at selectors. The judgment is real: which element, which assertion, what the recorded intent was.

Tool — not an agent

Jira

Deterministic REST calls. Wrapping a model around create_bug() buys latency, token cost, and a novel way to file a ticket that shouldn't exist. It became three plain tools.

Tool — not an agent

Risk prediction

Git churn, cyclomatic complexity, and an IsolationForest. There is no language model in it and it doesn't want one — it wants bug-history data. A tool, not an agent.

The reframe that made it 287 lines

The agent loop doesn't have to live in the codebase. Exposed over MCP, the client — Claude Code, Cursor, Claude Desktop — supplies the planning, retries, and conversation state. That deletes four orchestrators, four deployments, and four auth paths before any of them are written. The repo contributes what only it can: functions that do one thing and return JSON.

Engineering Decisions

Five choices that took longer to decide than to implement.

A gate the model cannot skip

Write tools use MCP elicitation — a prompt the human answers in the client UI, not an argument the model sets for itself. Where a client can't elicit, the tool returns a dry-run preview naming exactly what it would have written, and the test suite asserts Jira receives nothing on that path.

stdout is the wire

On stdio transport, a single stray print corrupts the JSON-RPC stream. Logging is pinned to stderr at boot and the wrapped modules were audited for print calls. Cheap discipline; silent, baffling breakage without it.

Heartbeats on long calls

A heal cycle takes minutes, and clients kill idle tool calls. The run tool reports progress every 30 seconds while the work proceeds — tested by collapsing the interval and asserting a beat lands before a slow run returns.

Errors that tell you what to do

Missing credentials return "enter them on the Settings page", not a stack trace. The model reads the sentence and relays it. Degradation is designed: with the database down, the credential-free tools still work.

Annotations, not just documentation

Read-only and destructive hints ship as MCP tool annotations, so clients can auto-allow safe tools and prompt before dangerous ones. The docs and the protocol assert the same thing, and a test enforces they stay in sync.

One tool deliberately not shipped

Test generation looked like a wrapper and wasn't: the session-to-BDD pipeline lives in a 330-line endpoint including a compile gate that keeps broken tests out of the framework. Shipping it meant either duplicating that gate or dropping it. Both are worse than waiting, so it was documented and deferred instead.

Verified, not assumed

Every claim was checked against a running system rather than a plan: a live stdio handshake returning all nine tools with annotations intact, a risk scan of 800 real files through the protocol, and a Jira query returning real tickets. Thirteen wiring tests run with no network and no model spend; the surrounding suite stayed green at 419.
